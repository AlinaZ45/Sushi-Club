# Sushi Club: состояние проверки 20.09.2026

## Основной проект

Используется существующий Vercel-проект `sushi-club-lara-api-v1352` и существующий Supabase-проект. Этот репозиторий — исходный код для него, а не новый сайт. GitHub Pages и ссылки на HTML через CDN не используются как способ публикации.

## Что проверено

- Названия и цены всех 51 позиции меню сопоставлены с присланным архивом v13.49: совпадают.
- Автономная проверка меню в Chromium: 51 карточка, 51 загруженная фотография; категории, поиск и сообщение об отсутствии результатов работают; ошибок JavaScript нет. Это НЕ проверка опубликованного сайта.
- Компонентная проверка гостевой формы с тестовым API: закрытое время недоступно; при сетевой ошибке все времена блокируются; двойное нажатие отправляет один запрос; e-mail гостя отеля попадает в поле e-mail, а не телефона. Реальные бронирования этим тестом не создавались.
- `scripts/build.mjs` проверяет целостность HTML, JavaScript и наличие всех 51 фотографии. Фотографии извлекаются в обычные файлы изображений; для них в браузере не нужен большой JavaScript-файл.
- Проверка в GitHub Actions для коммита `57642f8c9a3f5fa6147ddd0d12a3d69e9409f323` завершилась успешно: https://github.com/AlinaZ45/Sushi-Club/actions/runs/35506894734 . Это проверка сборки, НЕ публикация.
- В Supabase работает минутный вызов обработчика уведомлений. Проверенные ответы: HTTP 200, без тайм-аутов.
- В тестовой транзакции создаются уведомления гостю о запросе, подтверждении и отмене, а также сотруднику о новой и отменённой брони. Тестовые записи откатились; внешние сообщения не отправлялись.
- Закрыт доступ обычных пользователей к служебному секрету уведомлений. Убраны лишние права TRUNCATE/REFERENCES/TRIGGER для клиентских ролей на рабочих таблицах.

## Что НЕ завершено

1. Публикация исправленной сборки на основной Vercel-ссылке. Подключённая команда публикации возвращает `Tool deploy_to_vercel not found`. Требуется подключить этот репозиторий в настройках Git существующего проекта и создать развёртывание ветки main. Сборка настроена через `vercel.json`: `node scripts/build.mjs`, каталог `dist`.
2. Настройка отправителя e-mail: на момент проверки у обработчика отсутствовали настройки Resend. Нужны авторизованный аккаунт, подтверждённый отправитель и безопасное подключение серверных реквизитов. Подключение приложения Resend само по себе ещё не означает, что серверные реквизиты внесены и доставка проверена.
3. WhatsApp не подключён. Отправка, одобрение шаблона и согласие получателя не проверены.
4. Не завершён полный тест на опубликованном сайте: гостевая бронь → вход сотрудника → назначение столов → подтверждение → обновление статуса у гостя → получение сообщения → отмена/освобождение стола.
5. В текущем серверном коде вместимость сравнивается по точному времени начала бронирования. Длительность посещения и пересечение соседних времён ещё не моделируются. Требуются согласованное правило удержания стола и серверная защита от пересекающихся/одновременных назначений до полноценного запуска.
6. Для обработчика отправки ещё необходима проверка повторных вызовов и защиты от повторной отправки при сбоях. Наличие очереди не равно гарантированной доставке.

## Замечания проверки безопасности Supabase

- Служебные таблицы настроек и очереди имеют RLS без пользовательских политик намеренно: они не предназначены для чтения гостем или сотрудником через клиентский API. Пояснение: https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy .
- Проверка сообщает `pg_net` как расширение в public. Перед изменением проверить возможность переноса без остановки обработчика: https://supabase.com/docs/guides/database/database-linter?lint=0014_extension_in_public .
- Защита от скомпрометированных паролей ещё выключена: https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection .
